# Request path

How a proxied request travels from the client socket to the origin and back, and which Marasi clients reach the origin. Names are functions and types, so search for them. For anything inside one function, read the function.

In this map, bare "upstream" means the origin, as in `GLOSSARY.md`. An **upstream proxy** is a proxy that Marasi sends traffic through on its way to the origin. It is always written in full.

## Order

1. **Listener.** `(*Proxy).Listen` binds the socket, or a restart hands one over; `(*Proxy).WrapListener` and `(*Proxy).Serve` stack the listener wrappers. The raw socket is watched beneath protocol inspection and TLS, so a client that leaves is noticed while martian is not reading. `ProtocolMuxListener` inspects each new connection on its own goroutine, so a client that connects and sends nothing never delays the connections behind it.
2. **martian v2.1.0** reads the request and MITMs a `CONNECT`. It then runs the base pipeline's request step, then the round trip, then its response step. The whole request pipeline has run before anything goes upstream. Martian lives in one file, `martian_adapter.go` (`martianEngine`): it serves the listener, sets MITM, installs `(*Proxy).baseRequest` and `(*Proxy).baseResponse` (`options.go`) and owns the round tripper. Nothing else in marasi imports Martian, and no test does (repolint `martian-import`). The base pipeline reaches the client connection only through `clientHijacker`, kept on the pair. The engine is behind the `engine` interface (`engine.go`); Marasi's own HTTP/1.1 engine (`h1Engine`, `h1engine*.go`, on the `internal/h1` codec) replaces Martian only in a build with the internal `h1engine` tag or a test using `withH1Engine`, until the switch rewrites this map. It hands the request and response steps the raw wire message (`wireRequest`/`wireResponse`), so capture stores the wire form. The CA certificate is made with the standard library (`newCertificateAuthority`, `config.go`), with the same template Martian's `mitm.NewAuthority` used; Martian issues the leaf certificates.
   A `CONNECT` never enters the modifier chains. `WithBasePipeline` hands it to `(*Proxy).admitTunnel` (`tunnel.go`), the one admission hook: it marks the client connection as the proxy's own when the `CONNECT` carries `proxy.Client`'s credentials, and a refused project admission closes the connection. Compass scope and the loop check refuse no tunnel; they judge each request inside it. The self-client mark is `clientConnection.selfClient`, typed state on the tracked client connection, so it lasts for the whole connection.
3. **Request side.** `(*Proxy).baseRequest` handles admission, internal-client checks and header stripping, and builds the request's `Pair`. Before admission it reads the request body whole (`readRequestBody`, `body.go`) and records how it ended in `pair.RequestBodyEnding`; the body keeps its framing, and a cut-short body replays what arrived and then the read error. `watchClient` then watches the client socket, unless the body was cut short: then the round trip fails on the body's read error, which gets a proxy error response. `WithDefaultModifierPipeline` adds the modifiers, which run in the order they are added. Every request modifier is a `PairModifier`: it reads and edits typed pair fields, not context values (`pair_context.go` keeps the context in step, because each registered modifier reloads the pair from it and the transport and Lua response hooks still read it). A modifier ends the chain early with a control on the pair (`pair.go`): `Respond` answers locally (Marasi's own pages, a browser view, a loop), `Drop` drops the pair, and `Stop` lets the pair go on with no further modifier in this chain. A returned error means only that something broke. The chains are the proxy's unexported `requestModifiers` and `responseModifiers` (`ModifierGroup`), which stop at the first control or error; the base pipeline reads the control from the pair. A dropped request gets martian's empty 200 from `respondRoundTripper` and never goes upstream. A Go modifier error fails closed: `failRequestChain` (`proxy_error.go`) answers the pair with a 502 **proxy error response**, which never goes upstream, carries no `Warning` header and closes the client connection. A loop back to the listener gets one too (`PreventLoopModifier`).
4. **Capture.** The request is captured by its write modifier, before the round trip, and the response by its write modifier, after it. Both queue on `DBWriteChannel`, and `(*Proxy).WriteToDB` stores them.
5. **Round trip.** martian calls `respondRoundTripper` (`martian_adapter.go`), which returns the response a request modifier gave `Respond`, or the empty 200 of a dropped request, and sends nothing upstream. When the round trip gets no response (a dial or route failure), it answers with a 502 proxy error response instead of returning the error, so martian never makes its empty 502 with `Warning`. Every other request goes to `launchFailureRoundTripper`, which wraps `marasiRoundTripper`. `(*Proxy).Serve` builds it once around a `routedTransport` from `newRoutedTransport`. `routedTransport.RoundTrip` brings the route up to date, then takes an idle connection from that route's pool or dials a new one through the route. The transport gets its own copy of the request with `Close` cleared, so it adds no `Connection` line, and the response points back at the request martian holds. See [Route](#route).
6. **Response side.** `(*Proxy).baseResponse` reads the body whole (`readResponseBody`, `body.go`), records how it ended in `pair.ResponseBodyEnding`, sets its `Content-Length` and drops `Transfer-Encoding`, then admits project work again before the response modifiers run. It runs no response modifier for a request a request modifier answered or dropped, except a proxy error response whose request was captured: that one runs the response chain so it is stored with `metadata.proxy_error`, and Compass, the extensions and Checkpoint skip it because `pair.FromMarasi()` is true. `pair.FromMarasi()` tells a response Marasi made through `Respond` from the origin's. A dropped response closes the client connection. A cut-short response body stops the response side with `ErrReadBody`, and an upgrade's body, which is the connection, is left unread (`BodyUnread`). No size limit applies to either body, so nothing sets `BodyTooLarge` yet. Response modifiers take the pair (`func(*Proxy, *Pair) error`) and reach its request through `pair.Request`, never `res.Request`. A response modifier that runs a Lua hook goes through `callResponseHook`, which hands Lua a copy of the request carrying the pair's ID and metadata. No modifier touches a socket. When the whole chain has run and captured a 101, `baseResponse` calls `(*Proxy).handOffUpgrade` (`upgrade.go`): it takes the client connection through the pair's `clientHijacker`, clears the engine's connection deadline, writes the 101, and hands both connections to the registered `UpgradeHandler`. For WebSocket that is `WebSocketUpgradeHandler`, the relay, registered by `WithDefaultModifierPipeline`. `WebSocketPrepareModifier` still detaches the origin connection from the response body before the rest of the chain runs.

## Route

The route says how a new connection reaches the origin: directly, or through the upstream proxy that the open project selects. It is applied in the transport's dial step, and nowhere else.

- **Selection.** `Proxy.SelectUpstreamProxy` sets the selection from `ProjectResources.UpstreamProxy` when a project opens, and from `PUT /upstream-proxy-selection`. It dials nothing.
- **Resolve.** The `routeResolver` (`route_resolver.go`) combines the selection with this machine's list in `marasi_config.yaml` and returns a `Route`. It reads the YAML again only when the file's modification time or size changed. `Proxy.resolveRoute` runs it before each request takes a connection (in `routedTransport.RoundTrip`) and again for each new connection (in `dialOnCurrentRoute`). A hand edit, or a change from another instance sharing the config directory, therefore applies to the next request.
- **Swap.** When the resolved route differs from the current one, `Proxy.setRoute` swaps the atomic pointer and closes the idle connections of the old route's pool. The `routedTransport` keeps one `http.Transport`, a pool, per route (`routedTransport.poolFor`): a request takes its connection only from the current route's pool, so a connection that a request in flight hands back to the old pool after the swap can never carry a later request. That pool's idle connections are closed again when such a request finishes (`routedTransport.retire`). Every connection is a `routedConn` that carries the route that opened it. A dial that a swap overtook is discarded and runs again on the new route (`dialOnCurrentRoute`). The listener keeps running.
- **Dial.** `Route.dial` (`route_dial.go`) is the only place each scheme is dialled. It dials the origin's address, which is the waypoint's destination when a waypoint rewrote the URL host:
  - direct: TCP to the origin;
  - `http`: TCP to the upstream proxy, then `CONNECT host:port` with `Proxy-Authorization: Basic` when the entry has credentials. Plain-HTTP origins are tunnelled with `CONNECT` too;
  - `https`: the same `CONNECT` inside TLS to the upstream proxy (`route_tls.go`);
  - `socks5`: no authentication, or username/password when the entry has credentials, with the hostname sent unresolved (`route_socks5.go`).
- **Origin TLS.** For a TLS origin, the utls handshake then runs inside the connection that `Route.dial` returned. Both TLS legs verify against the system roots plus the entry's CA when it has one (`Route.rootCAs`, built once per route). Direct connections and other routes never trust that CA. A failed origin handshake through an upstream proxy is a `tls_verification` `*UpstreamProxyError`.
- **Fail closed.** A route that cannot carry the connection, or a selection missing from this machine's list, returns an `*UpstreamProxyError` and never a direct connection. `launchFailureRoundTripper` writes one ERROR proxy log naming the pair, the upstream proxy and the cause, and `respondRoundTripper` answers the client with a 502 proxy error response naming the cause.
- **Snapshot.** `SetupRequestModifier` puts a `core.RouteRecord` on the pair (`Pair.Route`), which reaches the transport through the request context. The `GotConn` trace in `routedTransport.RoundTrip` records the route of the connection that carried the request. A failed dial records the route its final attempt tried. `NewProxyResponse` copies the pair's record into `ProxyResponse.Route`, and `InsertResponse` stores it in `request.upstream_proxy_name` and `request.upstream_proxy_address`.
- **New engine.** Under the `h1engine` tag each client connection's origin connection is dialled through the same `routedTransport.dialPlain`/`dialTLS`, carries its route, and is replaced when the route resolved before a request differs. `setRoute` also closes the origin connections of client connections waiting for their next request, and an exchange a swap overtook closes its own afterwards; the client connection stays open (`h1engine_route.go`).
- **Check.** `Proxy.CheckUpstreamProxy` (`route_check.go`) resolves a named entry with a resolver of its own and dials once through a separate `newRoutedTransport` fixed to that route. It sends no request and leaves the selection alone.

## Who reaches the origin

Only the transport that `newRoutedTransport` builds connects to the origin. Tests build one whose route is always direct with `newDirectTransport`. `proxy.Client` sends through Marasi's own listener, so its requests run the whole path above and are captured; extensions use it. Launches and Armory requests do not go through an `http.Client`: `(*Proxy).sendRaw` (`launch_raw.go`) writes their raw text as bytes to the same listener on a new connection each (absolute form with the proxy's credentials for `http`, a `CONNECT` with them and then TLS for `https`), so the origin gets the header case, order and whitespace that were typed. `readRawRequest` reads the text with the `internal/h1` codec and rewrites only the value of each `Content-Length` line, adds one at the end only when there is none, no `Transfer-Encoding` and a body, and leaves the body's bytes alone. Every other `http.Client` in the repo is not proxy traffic: it reads a local CDP endpoint, fetches updates, or calls the control API.

## Where an outbound header comes from

Only these touch the headers a request goes upstream with:

- the sending client, which is `proxy.Client`'s transport for an extension's requests, and for a launch or Armory request the raw text as typed plus the internal fields `sendRaw` appends (`Proxy-Authorization`, `x-marasi-launch-id`, `x-armory-run-id`, `x-marasi-metadata`), which the base pipeline and `SetupRequestModifier` remove;
- the base pipeline (`baseRequest`);
- the request modifiers;
- `marasiRoundTripper.RoundTrip` and `routedTransport.RoundTrip`;
- Go's `http.Transport`.

An HTTP or HTTPS upstream proxy sees only the `CONNECT` and its `Proxy-Authorization`, and a SOCKS5 upstream proxy sees only its handshake. The tunnelled request carries no proxy headers, because the transport's `Proxy` field stays unset.
