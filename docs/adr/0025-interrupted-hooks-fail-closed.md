# Interrupted hooks fail closed

An extension hook is interrupted when its runtime's `ExecutionContext` is cancelled, by a project switch, service stop, or listener shutdown, or when the request context is cancelled, by a client disconnect. The interruption reaches the modifier as an ordinary Lua error, so the modifier tells it apart by context state after the hook returns. An interrupted hook fails closed. A request is dropped with `SkipRoundTrip` and `ErrDropped`, the same path a Lua drop takes. A response returns `ErrDropped`, and a WebSocket message is marked dropped. This applies to `processRequest`, `processResponse`, `processWebSocketMessage`, and the checkpoint extension's `interceptRequest`, `interceptResponse`, and `interceptWebSocketMessage`, because an unfinished hook may have been about to drop, change, or hold the item. Any other Lua error still fails open: it is logged and the item continues, so a faulty extension does not take traffic down.

**Considered options:** the transport refusing new round trips once proxy close begins. Rejected because it covers only proxy close. A client disconnect, and a project switch that cancels runtimes while the proxy listener stays up (ADR-0015), would still forward. It also does not cover responses or WebSocket frames, which do not make a new round trip.
