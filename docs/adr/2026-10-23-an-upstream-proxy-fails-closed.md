# An upstream proxy fails closed

When the open project selects an upstream proxy, traffic to the origin leaves only through it. If the upstream proxy refuses the connection, rejects its credentials, or times out, the request fails, the client gets an error, and a proxy log names the pair. If the project selects a name that this machine's list does not have, every request is refused the same way until `marasi upstream use` names a configured upstream proxy or `--none`, and the instance status says why. The proxy never falls back to connecting to the origin directly. A tester who selects an upstream proxy usually needs traffic to leave from one place, such as a client's jump box, an allow-listed source address, or a chained Burp, and a silent direct connection leaks traffic from the wrong place.

"All traffic to the origin" is everything that passes the transport, which includes launches, Armory, extensions, and the upstream leg of WebSocket connections. Plain HTTP is also tunnelled with CONNECT instead of being forwarded in absolute form, so the upstream proxy sees the bytes the proxy sends ([The proxy adds no headers to a request](2026-10-19-the-proxy-adds-no-headers-to-a-request.md)). A SOCKS5 upstream proxy resolves the host, so a target's name never reaches the local resolver. Update checks and CDP are not traffic to the origin and do not use it.

Each pair records the route that carried it, either the upstream proxy's name and address without credentials or direct, taken from the connection the request went out on. The record is a snapshot and does not change when the upstream proxy is renamed or removed.

**Considered options:** fall back to a direct connection; a fallback switch per upstream proxy; treat a missing name as none; refuse to open the project. Rejected because a fallback breaks the reason the upstream proxy was selected, a switch makes the unsafe behaviour one setting away, treating a missing name as none is the same fallback, and refusing to open stops a tester from reading the project's traffic.
