# Service owns proxy listener lifecycle state

A service instance reports its version, instance name, open project, and proxy listener through `GET /service/status`. The service package owns the instance identity, open project identity, and proxy-listener lifecycle state. `marasi.Proxy` processes traffic but does not own runtime listener control. The service lifecycle is also the shared listener implementation used by `marasi-app`. This lets every caller use one serialized state and one set of listener semantics while the open project remains independent.

Start and Update require a complete address and port. The lifecycle does not retain an endpoint after Stop. An inactive proxy listener is valid and appears as `null`; the service instance and control listener can remain running without it. Stop closes listener intake and live WebSockets but leaves accepted HTTP connections and the open project alone. Terminal Shutdown is separate because Martian closure is permanent. A missing open project is still an internal error because every service instance must control one open project. Project and listener reads are individually safe but do not form one atomic snapshot because their lifecycles are independent.

**Considered options:** retain the last endpoint; keep listener lifecycle in `marasi.Proxy`; extract a second neutral listener controller; keep separate listener loops in the service and `marasi-app`; close accepted HTTP connections on Stop; lock project and listener changes together. Rejected because callers can pass explicit endpoints, the proxy should not gain control responsibilities, another controller would split status and event ownership, duplicate loops would drift, Martian has no reusable accepted-connection drain, and one combined lock would couple independent lifecycles.
