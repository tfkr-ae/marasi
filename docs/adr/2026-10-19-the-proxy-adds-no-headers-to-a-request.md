# The proxy adds no headers to a request

A researcher launched a request with `Connection: keep-Alive`. The stored pair showed `Connection: close` added after it, and the origin received `Connection: close` twice. Go's HTTP transport adds headers on its own. With `DisableKeepAlives` it appends `Connection: close` to every request. With `Close` set it writes `Connection: close` unless the first `Connection` value already says close. With compression on it adds `Accept-Encoding: gzip` and decodes the response. Marasi now sends the headers of the original request exactly as written, adding none and removing none; it removes only its own internal headers, such as `x-marasi-launch-id`. Each launch still has a transport of its own, so it is the first request on a new connection and cannot be retried on a reused one, as [Launches are tracked and cancellable](2026-10-13-launches-are-tracked-and-cancellable.md) requires. Marasi closes that connection when the launch ends instead of setting `DisableKeepAlives`. Compression is off on the launch and Armory client and on the upstream transport. The upstream copy of each request is sent with `Close` unset, so the transport writes only the client's `Connection` lines.

**Consequences:** a request without `Accept-Encoding` now reaches the origin without one, so the origin usually answers uncompressed. Before, the transport asked for gzip and decoded the response, so the client and the stored pair never saw the encoding the origin used.
