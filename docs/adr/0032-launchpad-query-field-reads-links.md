# The launchpad query field reads links

Searching entries across launchpads needs a traffic query that knows about launchpads. `launchpad` is a declared traffic query field that reads the `launchpad_request` links, not the `launchpad_id` metadata, because a pair linked from captured traffic has no `launchpad_id` and a pair can be in more than one launchpad. `launchpad = "<launchpad id>"` matches pairs linked to that launchpad, `launchpad:*` matches pairs linked to any launchpad, each once, and `launchpad != "<launchpad id>"` is the complement of `=`: every pair not linked to that launchpad, including pairs in no launchpad. That follows the rule `!=` already has on other fields, where a pair without a value, such as an in-flight pair's status code, matches `!=` like it matches `NOT`. Each form translates to an `EXISTS` or `NOT EXISTS` subquery declared in code, with the launchpad id bound as a parameter. The value must be a quoted string that `uuid.Parse` accepts. Anything else, and any operator other than `=`, `!=`, and `:*`, is an invalid query with a position. A launchpad's entries take the same query: `GET /launchpad/{id}?q=` and `marasi launchpad get --query` read the launchpad's membership plus the translated query, through the one traffic query translator, and keep the entries oldest first. Oldest first is superseded by the entry order of ADR-0048 as the default order of a launchpad's entries.

**Considered options:** match `metadata.launchpad_id`; make `!=` match only pairs in some other launchpad; a separate query language or translator for launchpad entries. Rejected because the metadata misses linked captured traffic and holds only one launchpad, a `!=` that drops pairs in no launchpad would differ from `NOT launchpad = "<launchpad id>"` and from every other field's `!=`, and a second translator would let the two reads drift apart. `launchpad != "<id>" AND launchpad:*` gives pairs in some other launchpad.
