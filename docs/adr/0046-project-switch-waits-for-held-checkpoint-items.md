# A project switch waits for held Checkpoint items and says so

ADR-0015 refused a project switch while a Checkpoint item was held, and stopped a switch when a hold began during it, because forwarding or dropping an item went through the project gate that the switch had blocked. A researcher then had to resolve every item before switching, and a switch that met a late Lua hold failed with `project_busy` even when the hold was about to be resolved. A switch now waits for held Checkpoint items the way it waits for other project work. The Checkpoint routes are not admitted, since Checkpoint items live in memory and not in the open project, so a held item can be forwarded or dropped while the switch waits. A held WebSocket message is waited on before the switch closes live WebSockets. A hold that begins while the switch closes them is waited on too. An active Armory run still refuses the switch, because its client owns the run.

While a switch waits on project work, it reports what it waits for. After 500 ms of waiting, and then each time the list changes, the service publishes `project.waiting` with the target `project` and a `waiting_for` list. Each entry is a held Checkpoint item with its id, type, and first line; an extension whose Lua is running; or a count of other admitted requests and control calls. `project open` subscribes to events before it asks for the switch and, in human output, prints one `waiting for ...` line per entry on stderr. With `--json` it prints nothing extra, so its output stays one JSON value on stdout (ADR-0007). A client that leaves `project open` cancels the switch and keeps the current project.

**Considered options:** keep refusing and name the held items in the error; stream progress in the `/project/open` response; wait only for holds that begin during a switch. Rejected because a refusal still makes the researcher resolve and retry by hand, a streaming response changes the route's contract for every client, and an item held before the switch is the same project work as one held during it.
