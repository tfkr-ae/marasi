# Queries use AIP-160

A query is an AIP-160 filter string, parsed and type-checked by `go.einride.tech/aip/filtering` and translated by Marasi into SQL plus an FTS5 trigram `MATCH`. Traffic is the first collection with queries. Notes, findings, test cases, and WebSocket messages reuse the same grammar with their own declared fields. The control API takes it as `?q=` and the CLI as `--query`. The `host`, `method`, `path`, and `status_code` list parameters and flags are removed, so there is one way to narrow a list. The spec's precedence is kept as written, so `OR` binds tighter than `AND`. Text parts accept only `:`, text terms need at least three characters, and an invalid query is a 400 that names the problem and its position.

**Considered options:** pass raw FTS5 `MATCH` through, ANDed with structured parameters; a Marasi-specific query language; Lucene syntax through `go-lucene`; CEL. Rejected because raw FTS5 makes SQLite's grammar and errors a public contract and cannot express field equality or ranges, a custom language is a grammar to own forever, `go-lucene` renders `GLOB`/`LIKE`, which a contentless index cannot serve, and CEL reads as code rather than a search box.
