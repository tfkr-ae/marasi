# Client disconnect cancels the request

Martian stops reading a client socket while modifiers run, so a client that closes its connection mid-request went unnoticed, and the request context it reads with `http.ReadRequest` is never cancelled. ADR-0025 needs that cancellation to interrupt a hook. The proxy listener now watches each client socket beneath protocol inspection and TLS, the way `net/http` does: a background read runs while the request is in flight and cancels the request context on EOF or a read error. Bytes it reads are returned to the next read, and the next read ends the watch, so martian, MITM TLS, and the WebSocket hijack see the same stream. The watch starts once the request body has been read. A body of known length up to 1 MiB is read before the pipeline, since the request/response pair is stored whole anyway; a larger, chunked, or `Expect: 100-continue` body is watched once read through. A cancelled request also abandons its upstream round trip. A client that half-closes its write side counts as gone.

**Considered options:** patch martian's read loop; watch only during hooks; never read the body early. Rejected because martian is an external module, every in-flight stage including a round trip after a hook should stop for a client that has left, and without the early read a POST body blocks the watch for every request hook.
