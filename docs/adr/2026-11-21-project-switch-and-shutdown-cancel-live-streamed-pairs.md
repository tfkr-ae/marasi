# A project switch and a shutdown cancel live streamed pairs

A streamed pair (an SSE stream, a gRPC call) gives back its project admission once its heads went, so a switch that waits only for admitted work does not wait for it. It can stay open for as long as its peers keep it open. Before this decision, a switch went ahead under a live pair. The pair kept running the old project's extensions while the switch swapped them out, and it wrote its stream messages and its deferred response capture into the new project's database. Those writes failed on the `stream_messages.request_id` foreign key or leaked events across projects. A shutdown sent HTTP/2 clients a graceful GOAWAY and then waited for every stream, so one live gRPC or SSE stream kept `Close` from returning.

A project switch (`POST /project/open`), the release before a restart, a service stop and `Proxy.Close` now treat live streamed pairs as they treat live WebSockets ([Project switch publishes then releases](2026-10-06-project-open-then-release.md)). Each pair is cancelled as `stream cancel` cancels one: `RST_STREAM CANCEL` on HTTP/2, both connections closed on HTTP/1.1, and every direction still going recorded `cancelled`. The switch then waits until each pair has finished, so its messages and response are queued, and flushes them to the project the pair started in before it publishes the next. `Proxy.CloseLiveTrafficAndFlush` does all of this. A cancel is sticky, so a direction whose carry starts after the cancel is reset as it starts. While the proxy closes, a pair that starts is cancelled from the start.

A pair joins the live pairs a switch drains only once it is admitted in its project. A streamed request is read after its request was admitted. A streamed response joins once the response step admitted its head in the generation the request was captured in (`baseResponse`, `streamedPair.goLive`). A response head that waits for admission while a switch blocks the gate is not live, so the switch does not wait on work that waits on the switch. A pair whose request already went live is cancelled by the switch, and that cancel ends its response's wait for admission. A streamed response whose head is admitted after the project changed is refused as a stale upgrade is: the client gets Marasi's 502 and the origin's stream is reset or its connection closed. It is never carried, hooked, stored or announced in the project now open. A pair leaves the live pairs only after its response capture is queued and its end announced.

We rejected waiting for streamed pairs to end on their own because an event stream may never end, and a switch must not wait on the network ([A project switch never waits on the network](2026-10-17-project-switch-never-waits-on-the-network.md)). We rejected letting them run on, with each pair bound to the project it started in, because that keeps the old project's database and extensions alive after it is released.
