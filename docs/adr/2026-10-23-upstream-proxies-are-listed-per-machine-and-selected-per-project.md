# Upstream proxies are listed per machine and selected per project

The upstream proxies are a named list in `marasi_config.yaml`, shared by every service instance that uses that config directory. Each entry holds its URL, any credentials, and any extra trusted CA certificate copied in as PEM. The open project stores only the name it selects, as the setting `upstream_proxy.active` under the reserved client name `marasi`, so no migration is needed and clients cannot write it. Marasi reads this setting's meaning: [Client settings are opaque to Marasi](2026-10-14-client-settings-are-opaque.md) applies to clients' settings, and `marasi` is Marasi's own.

The split keeps credentials on the machine, so they never travel in a `.marasi` file, and keeps the choice of exit with the engagement, so opening an old project cannot send its traffic through another project's upstream proxy. Two service instances that run at once do not share a selection. A project opened on a machine without the selected name fails closed ([An upstream proxy fails closed](2026-10-23-an-upstream-proxy-fails-closed.md)).

The list is edited through the control API, as Chrome paths are. The service instance that makes the edit writes the YAML under the config lock and announces it. The other instances pick the edit up on their next connection, because the dialer reads the list again when the file's modification time changes, but they publish no event. Changing the selection does not restart the listener: requests in flight and open WebSocket connections finish on their route, idle connections on the old route are closed, and new connections use the new route.

**Considered options:** the list and the selection both in the project; both in the YAML; a per-instance selection held in memory; a typed project table for the selection. Rejected because a project list copies credentials into every `.marasi` file, a YAML selection follows the machine instead of the engagement and is contested by concurrent instances, an in-memory selection is lost on restart, and a table needs a migration for one value that the reserved client already holds.
