# A browser view serves the stored response once, at its original URL

A researcher wants to see how a captured response renders in a browser without sending the request again. Serving the stored response straight from `http://marasi/view/{uuid}` would render it on the wrong origin. Relative links, scripts, styles and images would break, and cookies, CSP and same-origin checks would behave differently from the real page. Instead, `marasi/view/{uuid}` redirects to the pair's original URL. The next request to that exact URL, from the same client address, gets the stored response without contacting the origin. This matches how Burp describes its *Show response in browser*.

The match ignores the method, because the redirect always produces a GET, and a captured POST response must still be viewable. A pending browser view is used once and expires after 10 seconds, so a redirect the browser never followed cannot take over a later real request. It is keyed on the host part of the client address, not on a token added to the URL, so the page sees its original URL unchanged. Marasi's own launches and Armory runs never match a pending browser view, even though they also come from the local machine. The stored response is copied when the browser view is registered, so matching never reads the project.

The stored response is served unchanged, including `Set-Cookie`, HSTS and cache headers, because a browser view must show exactly what was captured. Marasi's own redirect is sent with `no-store`. A browser view is handled before Compass, extensions, Checkpoint and capture, so it never creates a pair. The same now applies to the certificate page.

**Consequences:** a browser view can change browser state. A stored `Set-Cookie` can replace the live session cookie, and a cacheable stored page may later be served from the browser cache instead of the live site. Only the top-level navigation comes from storage. Everything the page loads afterwards reaches the live site, so an old page runs against today's backend. Every browser on the same machine has the same client address, so another local browser requesting the same URL within the 10 seconds can receive the stored response. Only a token in the URL could tell them apart, and that would change the URL the page sees.
