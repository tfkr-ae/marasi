# A project switch never waits on the network

ADR-0015 drains already-admitted HTTP before a project switch publishes, and a proxied request was admitted for its whole round trip. A request whose origin never answered therefore held `project open` for as long as the origin took, and nothing in the open project was being touched. Admission now covers only the work that touches the open project. The request side is admitted for scope, extensions, Checkpoint, taking the pair number, and queuing the pair's write, and is released before the round trip. The response side is admitted again once the response body has been read, so neither the wait for the headers nor the wait for the body holds a switch.

Each admission returns the generation of the open project, a counter that the switch advances when it publishes. The request records its generation. If the response side is admitted in the same generation, it runs as before. If not, the pair belongs to a project that is no longer open: the response goes to the client unchanged and skips every project-bound step, so the pair stays response-less in the project it was captured in. A WebSocket upgrade cannot be relayed without recording its connection and messages, so an upgrade answered after a switch gets `502 Bad Gateway` instead.

The same mechanism closes a gap in pair numbering (ADR-0042). Lua that started after the drain could still be admitted as nested work between the switch's last flush and publication, take a number from the old project, and have its write stored in the new one. The switch now seals admission at the moment it sees no project work, nested work included, so no work starts between that moment and publication. The flush after the seal is the last write to the old project, and work admitted after publication is in the new generation and uses the new project's number counter.

Lua hooks, nested Lua requests, held Checkpoint items, and WebSocket sessions are still project work, so a switch still waits for them, or refuses, as ADR-0015 describes.

**Considered options:** bounding the drain with a timeout; cancelling in-flight round trips on a switch; binding each queued write to a repository at enqueue. Rejected because a timeout either fails a switch or abandons work that is still project-bound, cancelling breaks a client whose request did nothing wrong, and enqueue binding is the larger change ADR-0015 already declined.
